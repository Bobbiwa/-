# 如何手写 Promise.all？

## 问题

请使用 JavaScript 实现一个面试版 `promiseAll`。它接收数组，支持普通值和 Promise；空数组应返回空结果；所有任务成功时结果保持输入顺序，任一任务失败时立即 reject。

## 30 秒口述答案

我会创建结果数组和完成计数器，遍历输入时用 `Promise.resolve` 统一处理普通值和 Promise。每一项完成后按原索引写入结果，所以最终顺序与输入一致；完成数量等于输入长度时整体 resolve。任一项失败直接调用外层 reject。空数组必须单独处理，否则没有回调会触发 resolve。

## 详细原理

### 为什么结果能保序

任务可以乱序完成，但每个回调记住自己的输入索引，并把结果写到 `result[index]`，因此返回数组不按完成顺序排列。

### 为什么使用 Promise.resolve

它可以统一接收普通值、原生 Promise 和 thenable，省去手动判断输入类型。

### 快速失败不等于取消

一个任务失败后，组合 Promise 会 reject，但其他已经开始的任务仍会继续执行。若要取消网络请求，需要额外使用 `AbortController` 等机制。

## JavaScript 示例

运行环境：现代浏览器或 Node.js 23.11.1。

```javascript
function promiseAll(list) {
  return new Promise((resolve, reject) => {
    if (list.length === 0) {
      resolve([]);
      return;
    }

    const result = [];
    let completed = 0;

    list.forEach((item, index) => {
      Promise.resolve(item).then((value) => {
        result[index] = value;
        completed += 1;

        if (completed === list.length) {
          resolve(result);
        }
      }, reject);
    });
  });
}

promiseAll([Promise.resolve(1), 2, Promise.resolve(3)])
  .then(console.log); // [1, 2, 3]
```

时间复杂度和空间复杂度都是 `O(n)`。

## 常见追问

1. **一个任务失败后其他任务会停止吗？** 不会，外层 Promise 失败不等于取消底层任务。
2. **为什么不能用 `push` 保存结果？** `push` 会按完成顺序保存，无法保证与输入顺序一致。
3. **`Promise.allSettled` 有什么不同？** 它会等待所有任务结束，并记录每项成功或失败，不会因某一项失败而提前 reject。

## 易错点

- 忘记处理空数组，导致返回 Promise 永远 pending。
- 使用 `push`，使输出顺序取决于完成顺序。
- 没有使用 `Promise.resolve`，普通值无法统一处理。
- 把快速失败理解成自动取消其他任务。
