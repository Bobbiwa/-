# TypeScript 如何通过类型守卫、可辨识联合和穷尽检查保证分支安全？

## 问题

什么是 TypeScript 的类型收窄？常见类型守卫有哪些？如何设计可辨识联合，并借助 `never` 保证新增业务分支时编译器能够提醒遗漏？

<details>
<summary>查看答案</summary>
<h2>30 秒口述答案</h2>
<p>类型收窄是 TypeScript 根据运行时判断和控制流，把一个宽类型在特定分支里缩小成更具体的类型。常见守卫有 <code>typeof</code>、<code>instanceof</code>、<code>in</code>、相等判断、<code>Array.isArray</code> 和返回类型谓词的自定义函数。业务状态最好设计成可辨识联合：每个成员都有同名的字面量字段，例如 <code>role: &quot;action&quot; | &quot;branch&quot; | &quot;loop&quot;</code>。<code>switch</code> 处理完所有成员后，把默认分支交给 <code>never</code>，新增成员却漏写分支时就会在编译期报错。</p>
<h2>详细原理</h2>
<h3>1. 收窄依赖运行时证据和控制流</h3>
<p>联合类型只允许直接执行所有成员都支持的操作。条件判断提供新的证据后，TypeScript 的控制流分析会沿着分支、提前返回和赋值关系更新变量类型。例如 <code>typeof value === &quot;string&quot;</code> 后才能安全调用字符串方法。</p>
<p>常见守卫各有边界：</p>
<ul><li><code>typeof</code> 适合原始类型，但 <code>typeof null === &quot;object&quot;</code>，检查对象时必须排除 <code>null</code>；</li><li><code>instanceof</code> 依赖运行时构造函数与原型链，不能检查只存在于编译期的 <code>interface</code>；</li><li><code>in</code> 检查属性是否存在于对象或其原型链上，不等于属性值有效；</li><li>真值判断会同时排除 <code>0</code>、<code>&quot;&quot;</code>、<code>false</code>，业务若允许这些值就不能笼统使用；</li><li>自定义类型谓词 <code>value is T</code> 的实现由开发者负责，谓词写错会让编译器得到错误前提。</li></ul>
<h3>2. 可辨识联合让数据模型与分支一一对应</h3>
<p>可辨识联合要求每个成员拥有一个共同字段，并且该字段是互斥的字面量类型。与“一个大接口加很多可选字段”相比，它能表达：当 <code>role</code> 是 <code>branch</code> 时一定存在 <code>paths</code>，当 <code>role</code> 是 <code>loop</code> 时一定存在 <code>children</code>。检查 <code>role</code> 后，TypeScript 会自动得到对应成员，无需到处使用非空断言。</p>
<p>辨识字段应稳定且语义明确。若后端传入任意字符串，仍需先在运行时验证，不能因为前端声明了联合类型就假设外部数据正确。</p>
<h3>3. <code>never</code> 把遗漏变成编译错误</h3>
<p>当所有联合成员都被排除后，剩余变量的类型是 <code>never</code>。默认分支调用 <code>assertNever(step)</code>，当前联合完整时可以通过；将来加入新成员而忘记处理时，新成员不能赋给 <code>never</code>，编译器便会指出遗漏位置。</p>
<p>这比默默返回默认值更适合核心状态机和协议转换，因为默认值可能掩盖新业务状态。对于确实需要向前兼容的外部协议，则应显式设计 <code>unknown</code> 分支并记录降级策略，而不是假装穷尽。</p>
<h2>TypeScript 示例（TypeScript 5.9，Node.js 或浏览器）</h2>
<pre><code class="language-typescript">interface ActionStep {&#10;  role: &quot;action&quot;;&#10;  id: string;&#10;  operation: string;&#10;}&#10;&#10;interface BranchStep {&#10;  role: &quot;branch&quot;;&#10;  id: string;&#10;  paths: Step[][];&#10;}&#10;&#10;interface LoopStep {&#10;  role: &quot;loop&quot;;&#10;  id: string;&#10;  children: Step[];&#10;}&#10;&#10;type Step = ActionStep | BranchStep | LoopStep;&#10;&#10;function assertNever(value: never): never {&#10;  throw new Error(`未处理的步骤：${JSON.stringify(value)}`);&#10;}&#10;&#10;function countSteps(steps: readonly Step[]): number {&#10;  return steps.reduce((total, step) =&gt; {&#10;    switch (step.role) {&#10;      case &quot;action&quot;:&#10;        return total + 1;&#10;      case &quot;branch&quot;:&#10;        return total + 1 + step.paths.reduce(&#10;          (sum, path) =&gt; sum + countSteps(path),&#10;          0,&#10;        );&#10;      case &quot;loop&quot;:&#10;        return total + 1 + countSteps(step.children);&#10;      default:&#10;        return assertNever(step);&#10;    }&#10;  }, 0);&#10;}&#10;&#10;const workflow: Step[] = [&#10;  { role: &quot;action&quot;, id: &quot;a1&quot;, operation: &quot;fetch&quot; },&#10;  {&#10;    role: &quot;loop&quot;,&#10;    id: &quot;l1&quot;,&#10;    children: [{ role: &quot;action&quot;, id: &quot;a2&quot;, operation: &quot;send&quot; }],&#10;  },&#10;];&#10;&#10;console.log(countSteps(workflow)); // 3</code></pre>
<p>如果新增 <code>interface DelayStep { role: &quot;delay&quot;; ... }</code> 并把它加入 <code>Step</code>，但没有给 <code>switch</code> 添加 <code>delay</code> 分支，<code>assertNever(step)</code> 会产生类型错误。</p>
<h2>常见追问</h2>
<ol><li><strong>类型谓词和类型断言有什么区别？</strong> 谓词函数应通过运行时逻辑提供可复用证据；断言不执行检查，只覆盖编译器判断。</li><li><strong>为什么不把所有成员字段都放进一个接口并标成可选？</strong> 那样无法表达字段之间的关联，分支内部仍会遇到 <code>undefined</code>，也容易构造出业务上无效的组合。</li><li><strong><code>default</code> 分支直接抛错是否等于穷尽检查？</strong> 运行时能兜底，但只有让剩余值满足 <code>never</code> 才能在新增联合成员时得到编译期提醒。</li></ol>
<h2>易错点</h2>
<ul><li>用 <code>if (value)</code> 收窄时误伤合法的 <code>0</code>、空字符串或 <code>false</code>。</li><li>认为 <code>in</code> 已经验证了属性值的类型，实际上还需继续检查值。</li><li>编写不可靠的 <code>value is T</code> 谓词，让声明与实际检查不一致。</li><li>用多个布尔字段表达互斥状态，产生“同时为真”或“全部为假”的非法组合。</li><li>在 <code>switch</code> 的默认分支返回普通默认值，导致新增联合成员时静默漏处理。</li></ul>
