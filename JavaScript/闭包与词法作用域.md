# 什么是闭包？它与词法作用域有什么关系？

## 问题

什么是 JavaScript 闭包？它为什么能在外层函数返回后继续访问外层变量？闭包捕获的是变量当时的值还是绑定？请说明它在异步回调、循环和资源清理中的常见应用与风险。

<h2>30 秒口述答案</h2>
<p>闭包可以理解为函数和它定义时可访问的词法环境的组合。JavaScript 是词法作用域，名字解析取决于函数写在哪里，而不是从哪里调用。只要内部函数仍可达，它需要的外层绑定就可以继续存活，所以外层函数返回后仍能读取或修改这些绑定。闭包通常捕获的是绑定，不是自动冻结的值，因此之后对绑定的修改会被回调看到。它常用于私有状态、回调和异步控制；闭包本身不是内存泄漏，只有无用闭包长期可达并保留大对象或资源时才形成问题。</p>
<h2>详细原理</h2>
<h3>1. 词法作用域决定查找路径</h3>
<p>词法作用域由源码嵌套结构决定。函数体访问一个局部没有声明的名字时，会沿定义位置对应的外层 Environment Record 查找，而不会改用调用者的局部作用域。</p>
<p>ECMAScript 普通函数对象带有内部槽 <code>[[Environment]]</code>，记录函数创建时关联的外层环境。调用函数时又会建立本次调用的函数 Environment Record，并以保存的外层环境连接作用域链。日常所说的“闭包”就是这一语言机制表现出的能力；它不是手动复制一张变量表。</p>
<h3>2. 为什么外层函数返回后变量还能存在</h3>
<p>外层函数调用结束意味着它的执行上下文退出调用栈，不等于其全部环境立即销毁。如果返回的函数、定时器回调、Promise 回调或事件监听器仍可达，并且需要该环境，相关绑定就必须保留。等这些函数和环境不再可达后，垃圾回收器才有机会回收它们；具体回收时机属于实现细节，代码不能依赖某个确定时刻。</p>
<p>每次调用外层函数通常会建立独立的函数环境，所以工厂函数创建出的多个计数器可以拥有互不干扰的状态。</p>
<h3>3. 捕获绑定，不是自动保存快照</h3>
<p>闭包通常读取的是词法环境中的绑定。外层代码后来给同一绑定重新赋值，闭包再次执行时会看到新值。若业务需要创建当时的快照，应在当次作用域中建立不会再改绑的局部绑定，或显式复制所需数据；对象快照还要考虑浅拷贝与深拷贝语义。</p>
<p>经典循环问题也来自绑定是否共享：<code>var</code> 循环中的多个回调通常共享同一个函数级绑定；<code>for</code> 头部的 <code>let</code> 会为各次迭代建立对应绑定，所以回调得到 <code>0、1、2</code>。</p>
<h3>4. 常见用途与生命周期风险</h3>
<ul><li><strong>封装状态：</strong> 工厂函数返回操作函数，外部只能通过规定接口访问内部状态。</li><li><strong>异步控制：</strong> Promise、timer 或 React Effect 的回调共享某次操作的状态，例如请求是否已失效。</li><li><strong>函数配置：</strong> 柯里化、偏函数和事件处理器可保留创建时的配置。</li><li><strong>防抖与节流：</strong> 多次调用共享 timer binding，以取消或复用之前的调度。</li></ul>
<p>闭包不会天然造成内存泄漏。真正的风险是本应失效的 timer、事件监听器、订阅或缓存仍然可达，使闭包连带保留大对象。应在生命周期结束时清理外部注册，并避免无意捕获整个大对象。现代引擎可以优化环境保存方式，但这属于实现策略，面试时不应承诺某个变量一定如何分配或回收。</p>
<h2>JavaScript 示例（Node.js 23）</h2>
<pre><code class="language-javascript">&quot;use strict&quot;;&#10;&#10;function createCounter(initialValue) {&#10;  let count = initialValue;&#10;&#10;  return {&#10;    increment() {&#10;      count += 1;&#10;      return count;&#10;    },&#10;    read() {&#10;      return count;&#10;    },&#10;  };&#10;}&#10;&#10;const first = createCounter(0);&#10;const second = createCounter(10);&#10;console.log(first.increment()); // 1&#10;console.log(first.read()); // 1&#10;console.log(second.read()); // 10：来自另一次调用的独立环境&#10;&#10;let current = &quot;before&quot;;&#10;const readCurrent = () =&gt; current;&#10;current = &quot;after&quot;;&#10;console.log(readCurrent()); // after：读取同一个绑定，不是创建函数时的字符串快照&#10;&#10;const delay = (milliseconds) =&gt; new Promise((resolve) =&gt; {&#10;  setTimeout(resolve, milliseconds);&#10;});&#10;&#10;function startJob() {&#10;  let cancelled = false;&#10;&#10;  const done = (async () =&gt; {&#10;    await delay(0);&#10;    return cancelled ? &quot;cancelled&quot; : &quot;completed&quot;;&#10;  })();&#10;&#10;  return {&#10;    cancel() {&#10;      cancelled = true;&#10;    },&#10;    done,&#10;  };&#10;}&#10;&#10;(async () =&gt; {&#10;  const job = startJob();&#10;  job.cancel();&#10;  console.log(await job.done); // cancelled&#10;})();</code></pre>
<p>这个异步示例中的 <code>cancel</code> 只改变共享状态，并没有取消底层 timer。真实业务若要释放资源，还需要相应的 <code>clearTimeout</code>、<code>AbortController</code>、取消订阅或移除监听器。</p>
<h2>常见追问</h2>
<ol><li><strong>闭包捕获的是值还是变量？</strong> 更准确地说，它通过词法环境访问绑定。绑定后来重新赋值时，闭包通常会读到新值；需要快照时要另建绑定或显式复制数据。</li><li><strong>闭包为什么可能与内存泄漏有关？</strong> 只要闭包仍可达，它依赖的环境也可能被保留。泄漏的根因通常是忘记清理监听器、timer、订阅或无限增长的缓存，而不是“用了闭包”本身。</li><li><strong><code>var</code> 和 <code>let</code> 为什么让循环回调得到不同结果？</strong> 多个 <code>var</code> 回调共享同一函数级绑定，循环结束时它已是最终值；<code>for</code> 中的 <code>let</code> 会为各次迭代建立对应绑定。</li></ol>
<h2>易错点</h2>
<ul><li>认为只有“外层函数返回内部函数”才算闭包；事件处理器、Promise 回调等同样可以闭合外层环境。</li><li>认为闭包保存了创建瞬间所有变量的值；它通常关联的是绑定，且不相关变量是否被优化属于实现细节。</li><li>把“执行上下文出栈”误解成外层环境必定立即销毁，忽略可达闭包仍需该环境。</li><li>笼统地说“闭包一定内存泄漏”，没有说明可达性和资源生命周期。</li><li>用布尔 <code>cancelled</code> 阻止后续状态写入后，就宣称底层请求或 timer 已被取消。</li></ul>
