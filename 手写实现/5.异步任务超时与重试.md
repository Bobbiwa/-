# 如何实现异步任务超时与重试？

## 问题

请使用 JavaScript 分别实现 `withTimeout(task, ms)` 和 `retry(task, maxAttempts, delay)`：前者在任务超过指定时间时 reject，后者在任务失败后按固定间隔继续尝试，直到成功或达到最大尝试次数。

## 30 秒口述答案

超时可以用 `Promise.race`，让业务任务和一个定时 reject 的 Promise 竞争，谁先 settled 就采用谁的结果。重试则用循环包住 `await task()`，失败时判断是否还有机会，没有就抛出最后一次错误，有则等待固定时间再继续。需要强调的是，超时只让包装 Promise 失败，不会自动停止底层任务；真正取消要让任务配合 `AbortController`。

## 详细原理

### 超时

业务 Promise 和 timeout Promise 同时参与 `Promise.race`。如果业务先完成，返回业务结果；如果 timer 先触发，外层以超时错误 reject。

### 重试

`maxAttempts` 表示包含首次执行在内的最大尝试次数。例如传入 `3`，最多执行三次。每次失败后，只有仍有下一次机会才等待 `delay`。

### 面试版边界

本实现使用固定延迟，没有区分错误类型，也没有实现指数退避和随机抖动。超时后底层任务可能仍在运行；生产请求还要考虑幂等性、HTTP 状态码和服务端的 `Retry-After`。

## JavaScript 示例

运行环境：现代浏览器或 Node.js 23.11.1。

```javascript
function withTimeout(task, ms) {
  let timer;
  const timeout = new Promise((_, reject) => {
    timer = setTimeout(() => reject(new Error("请求超时")), ms);
  });

  return Promise.race([Promise.resolve().then(task), timeout])
    .finally(() => clearTimeout(timer));
}

function sleep(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function retry(task, maxAttempts, delay = 0) {
  let lastError;

  for (let attempt = 1; attempt <= maxAttempts; attempt += 1) {
    try {
      return await task(attempt);
    } catch (error) {
      lastError = error;
      if (attempt < maxAttempts) await sleep(delay);
    }
  }

  throw lastError;
}

let count = 0;
retry(() => withTimeout(() => {
  count += 1;
  if (count < 3) throw new Error("暂时失败");
  return "成功";
}, 3000), 3, 500)
  .then(console.log)
  .catch(console.error);
```

若最多尝试 `k` 次，包装逻辑的空间复杂度为 `O(1)`；总耗时取决于每次任务时间和重试间隔。

## 常见追问

1. **超时后 fetch 会自动停止吗？** 不会。需要创建 `AbortController`，在超时时调用 `abort()`，并把 signal 传给 fetch。
2. **哪些错误不应该重试？** 参数错误、权限错误和不安全的非幂等写操作通常不应盲目重试。
3. **为什么生产环境常用指数退避和随机抖动？** 它们可以降低持续故障时的压力，并避免大量客户端同时重试。

## 易错点

- 把 `maxAttempts` 和“额外重试次数”混淆，造成多执行或少执行一次。
- 最后一次失败后仍然等待一个没有意义的 delay。
- 认为 `Promise.race` 超时后会自动取消业务 Promise。
- 对所有错误和非幂等请求无条件重试。
