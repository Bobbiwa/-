> 目标：用自己的话来解释 每个核心业务操作背后的大致细节。

你可以把这四个场景当成闯关游戏，尝试用大白话把它们背后的“数据流转过程”串出来。

### 场景一：拖拽改变节点顺序（核心业务流转）

**用户在屏幕上的操作：** 用户鼠标按住一个“动作节点”，把它拖拽到了两个节点中间的“插入槽位（DropZone）”上，然后松开鼠标。

**你需要理清的思路线：**

1. 鼠标松开的那个瞬间，`@dnd-kit/react` 触发了哪个生命周期事件？   
2. 代码是如何判断用户是在“拖拽排版”而不是单纯的“点击”？   
3. 判定为拖拽后，Zustand 里的 `flowSlice.steps` 发生了什么结构上的变化？（提示：存的是像素坐标，还是数组索引的改变？）   
4. 在拖拽排序中，如果源节点和目标槽位在**同一个数组**里，且源节点的下标**小于**目标下标，当你在原位置把节点删除后，目标位置的下标是不是会发生“左移错位”？你在代码里是怎么做索引补偿的？
5. `steps` 数组变了之后，界面上的 DOM 节点和 SVG 连线是怎么知道要重新画到新位置的？（提示：`layoutFlow` 函数的作用）   

### 场景二：滚轮缩放与平移（视口与渲染隔离）

**用户在屏幕上的操作：** 流程图非常大，用户按住 Ctrl/Cmd 键，对着画布某一个节点滚动鼠标滚轮，画布开始放大。

**你需要理清的思路线：**

1. 高频的滚轮事件触发后，为了不卡顿，代码是立刻去 `setState`，还是通过什么机制把几百个事件合并成了一帧？   
2. 当最新的缩放倍率（Zoom）计算出来后，它会触发 `layoutFlow` 重新计算每个节点和每条连线的坐标吗？   
3. 既然节点本身的坐标没有重新算，那整个画面是怎么实现放大效果的？（提示：单一父级的包裹容器做了什么？）   

### 场景三：单击打开右侧配置面板（复杂交互降级）

**用户在屏幕上的操作：** 用户只是用鼠标轻轻“单击”了一下某个可拖拽的逻辑节点，右侧顺利弹出了这个节点的配置面板。

**你需要理清的思路线：**

1. 正常情况下，加入了拖拽库后，原生的 `onClick` 事件会被吃掉。系统是在什么地方“拦截”并识别出这是一个单击动作的？   
2. 识别出单击后，触发了哪个状态切片（Slice）的更新，从而让右侧面板知道要渲染哪个节点的数据？   

### 场景四：AI 生成流程图（前后端工程闭环）

**用户在屏幕上的操作：** 用户在对话框输入“帮我建一个工作流，当收到新邮件时发一条飞书消息”，点击发送，画布上开始流式出现节点。

**你需要理清的思路线：**

1. 前端发请求时，是直接把大模型的结果扔进画布吗？服务端在发给 OpenAI 之前，偷偷往 Prompt 里塞了什么核心约束？（提示：能力目录 Capability Catalog）   
2. OpenAI 返回一段 JSON 后，服务端在通过 SSE 流式推给前端之前，做了哪几步最关键的“拦截与校验”？
