# JavaScript 中原始值与对象在赋值和传参时有什么区别？

## 问题

JavaScript 中，把一个原始值或对象赋给另一个变量时分别发生了什么？把它们传给函数后，为什么修改对象属性会影响外部对象，而给形参重新赋值不会？JavaScript 到底是按值传递还是按引用传递？

> [!note]- 查看答案
>
> ## 30 秒口述答案
>
> JavaScript 的赋值和函数传参传递的都是值，不存在能让形参直接改绑实参变量的“按引用传参”。原始值本身不可变，复制后两个变量各自保存这个值；对象也是一种值，赋值或传参后，新旧变量指向同一个对象，所以通过任一变量修改对象属性，另一边都能观察到。可是给形参重新赋一个对象，只会改变函数内部的局部绑定，不会改变调用方变量。`const` 只禁止重新赋值，不会让对象自动变成不可变对象。
>
> ## 详细原理
>
> ### 1. 原始值与对象
>
> ECMAScript 的原始类型包括 `Undefined`、`Null`、`Boolean`、`String`、`Symbol`、`Number` 和 `BigInt`，其余可直接操作的复合值属于对象；函数本身也是对象。
>
> 原始值不可变。例如字符串方法不会在原字符串内部改字符，而是返回新值。变量可以从一个原始值重新绑定到另一个原始值，但这不是修改原始值本身。
>
> 对象具有 identity 和可变属性。两个变量保存同一个对象值时，它们观察的是同一个对象；修改其属性不是给这两个变量重新赋值。
>
> ### 2. 赋值复制的是什么
>
> - 对原始值赋值，右侧计算出的原始值被保存到左侧绑定中，之后重新赋值互不影响。
> - 对对象赋值，右侧计算出的对象值被保存到左侧绑定中，并不会隐式克隆对象。因此两个绑定可以指向同一个对象。
> - 工程交流中常把后一种情况简称为“复制了引用”，但不能由此推导出 JavaScript 函数是按引用传参。规范层面传入的是求值后的参数值。
>
> 展开语法 `{ ...source }`、`Object.assign` 等只能复制一层自有属性；如果属性值仍是对象，新旧对象的该属性仍可指向同一个嵌套对象。它们不是通用深拷贝。
>
> ### 3. 函数参数为什么表现不同
>
> 调用函数时，每个实参表达式先求值，得到的值用于初始化对应的形参绑定。因此：
>
> - 形参接收原始值后，给形参重新赋值不会影响调用方绑定。
> - 形参接收对象值后，通过形参修改该对象的属性，调用方能看到同一对象发生了变化。
> - 给形参重新赋一个新对象，只会让局部形参改为保存新对象，不会改绑调用方变量。
>
> 判断是否“按引用传参”的关键反例是：如果函数真的拿到了调用方变量本身的引用，那么给形参重新赋值也应该改掉调用方变量；JavaScript 并不会这样做。
>
> ### 4. `const` 约束的是绑定
>
> `const user = { name: "A" }` 禁止执行 `user = anotherUser`，但允许 `user.name = "B"`。若需要限制对象属性被修改，可以根据场景使用 `Object.freeze`、不可变更新或只读类型；其中 `Object.freeze` 默认也只是浅冻结。
>
> ## JavaScript 示例（Node.js 23）
>
> ```javascript
> "use strict";
>
> let count = 1;
> let copiedCount = count;
> copiedCount = 2;
> console.log(count, copiedCount); // 1 2
>
> const original = { profile: { name: "小杜" } };
> const alias = original;
> alias.profile.name = "Du";
> console.log(original.profile.name); // Du
> console.log(alias === original); // true
>
> function update(user, number) {
>   user.profile.name = "updated"; // 修改双方共享的对象
>   user = { profile: { name: "local" } }; // 只改绑局部形参
>   number = 99; // 只改绑局部形参
>   return { user, number };
> }
>
> let outsideNumber = 10;
> const returned = update(original, outsideNumber);
>
> console.log(original.profile.name); // updated
> console.log(outsideNumber); // 10
> console.log(returned.user.profile.name); // local
> console.log(returned.user === original); // false
>
> const shallowCopy = { ...original };
> shallowCopy.profile.name = "shared nested object";
> console.log(original.profile.name); // shared nested object
> console.log(shallowCopy === original); // false
> console.log(shallowCopy.profile === original.profile); // true
> ```
>
> 对象赋值和传参在语言语义上不会遍历或克隆对象内容；常见实现只复制内部的引用式值，但 ECMAScript 不规定具体存储方式或时间复杂度。对象展开需要枚举一层属性，成本会受被复制属性数量及访问行为影响，且不会递归复制嵌套对象。
>
> ## 常见追问
>
> 1. **为什么很多资料会说对象是“引用传递”？** 这通常是在描述多个变量能够访问同一对象的现象。更严谨的说法是对象值按值传递；形参拿到同一个对象值，但拿不到调用方变量的绑定。
> 1. **`const` 对象为什么还能修改？** `const` 限制变量绑定不能重新赋值，不限制对象内部属性；它与对象是否可变是两个维度。
> 1. **展开语法能解决对象互相影响吗？** 只能切断最外层对象的 identity；嵌套对象仍然共享。是否需要 `structuredClone` 或业务化深拷贝，要看值类型、性能和语义要求。
>
> ## 易错点
>
> - 把“共享同一对象”直接说成“JavaScript 按引用传参”，忽略形参重新赋值不会影响实参绑定。
> - 认为原始值存在可被原地修改的内部内容；实际上改变变量只是让绑定保存另一个值。
> - 认为 `{ ...object }` 是深拷贝，忽略嵌套对象仍然共享。
> - 认为 `const` 会递归冻结对象，或认为 `Object.freeze` 默认会递归冻结嵌套对象。
> - 把 `null` 当成对象；`typeof null === "object"` 是历史兼容结果，`null` 在语言类型中仍是原始值。
