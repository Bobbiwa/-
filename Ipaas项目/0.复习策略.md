# 复习策略

> 忘记项目细节，怎么办？

这是一种非常典型的“AI 辅助后遗症”。当借助 AI 快速写完大量代码后，功能虽然跑通了，但你的大脑并没有建立起从 0 到 1 的“神经元连接”。这不是你的技术能力问题，而是由于开发速度过快导致的认知同步脱节。

要破解这个局面，**绝对不要去逐行翻看源码**，那只会让你陷入无尽的细节黑洞，越看越焦虑。面试官并不关心某个具体的变量名或某一行具体的 API 传参，他们真正在意的是你对**系统流转逻辑**的掌控力。

接下来的几天，我们需要执行一套“自顶向下，重塑大脑沙盘”的策略，把这个项目真正吃透，变成你自己的护城河：

第一步是**建立物理直觉，跑通主干数据流**。不要看代码，直接打开你的 iPaas 平台。在界面上拖拽一个节点、连上一条线、触发一次 AI 编排，同时在脑子里强迫自己回答：这个操作触发了哪个 Zustand action？它是如何通知 `layoutFlow` 函数重新计算坐标的？计算完之后，又是怎么流向 DOM 和 SVG 进行混合渲染的？只要你能把这层数据流转的“因果关系”用大白话串起来，你对项目的宏观掌控感瞬间就能回来。   

第二步是**绘制属于你的“战术地图”**。拿出一张白纸，屏蔽代码细节，画出这个系统的四大核心边界：React 页面层（负责 UI 与视口拖拽）、流程编辑器层（负责坐标与拖放派生）、状态层（Zustand 里的 `Step[]` 递归流程树）、以及服务端的确定性编译与校验。在面试中，只要你的回答没有逃出这张大图的边界，你就永远不会被问倒。当面试官问一个刁钻细节时，你可以从容地把它归类：“这个细节是在我们的纯几何布局引擎里处理的，它的输入是业务状态树，输出是坐标集合……”这就是高级工程师的架构视野。   

第三步是**通过逆向防御演练建立肌肉记忆**。你不需要掌握 100% 的细节，只要掌握那 20% 能决定项目成败的核心决策即可。这包括为什么坚决不用 Canvas 而选 DOM+SVG，为什么节点不存物理坐标而存数组索引，以及 dnd-kit 吞噬点击事件时你是如何破局的。我会扮演面试官，专门挑出这几个核心刺客问题来考你。第一遍你肯定会结巴，第二遍我会帮你精简提炼，第三遍它就会长在你的嘴巴上，变成极其自然的肌肉记忆。   

为了迈出重塑掌控感的第一步，我们可以先做一个极其简单的微观推演：当你在画布上把一个节点拖到另一个位置松手时，结合你项目里的 Zustand 和 `Step[]` 数组，底层到底发生了哪最关键的两到三步？
