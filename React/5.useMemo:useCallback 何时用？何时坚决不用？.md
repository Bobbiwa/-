这道题是检验前端“性能优化”基本功的试金石。

很多初中级开发者有一种“性能强迫症”：既然每次渲染都会重新创建函数和变量，那干脆给所有的函数套上 `useCallback`，所有的变量套上 `useMemo`，不就完美了吗？

如果在面试时你流露出这种想法，面试官会直接给你打上“缺乏底层常识”的标签。因为**优化本身是需要成本的**。

我们用“买保险柜”来比喻：`useMemo` 和 `useCallback` 就是保险柜。如果你为了保护一张 1 块钱的纸币（极简的计算），花 100 块钱买了个保险柜（依赖对比的内存和计算开销），这就是典型的**负优化**。

### 🚫 什么时候绝对不要用？（负优化灾难区）

**1. 传递给原生的 DOM 元素时（毫无意义）**

JavaScript

```
// ❌ 灾难示范：强行给原生 button 绑定的事件加 useCallback
const handleClick = useCallback(() => {
  console.log("点击了");
}, []);

return <button onClick={handleClick}>提交</button>;
```

原生 DOM 元素（如 `div`, `button`, `input`）根本不在乎你传进来的函数引用是不是变了。就算你每次渲染都给它一个全新的箭头函数，浏览器的渲染引擎也能极快地处理，完全不会触发额外的 DOM 重绘。在这里用 `useCallback`，你纯粹是在白白消耗 React 引擎在底层对比依赖数组（`[]`）的性能。

**2. 极其廉价的简单计算（得不偿失）**

JavaScript

```
// ❌ 灾难示范：极其简单的数组衍生
const userNames = useMemo(() => users.map(u => u.name), [users]);
```

对几十条数据的数组做个 `map`，或者做几个数字的加减乘除，JS 引擎执行只需要 0.001 毫秒。但是 `useMemo` 在底层需要分配闭包内存、甚至要去遍历对比 `users` 是否发生了变化，这个“对比成本”往往远大于“计算成本”本身。

### ✅ 什么时候必须用？（真正的用武之地）

使用这两个 Hook 的核心目的只有两个：**阻断无意义的组件重渲染**，或者 **提供稳定的依赖项**。

**1. 配合 `React.memo` 阻断沉重子组件的渲染**

这是 `useCallback` 最核心的价值所在。

假设你有一个非常复杂的 `<HeavyChart/>`（图表组件），内部渲染要花费 500ms。如果你不把它包在 `React.memo` 里，父组件一更新，它就跟着更新。

JavaScript

```
// 父组件
function Dashboard() {
  const [text, setText] = useState("");

  // ✅ 正确示范：为了不让 Chart 跟着输入框的 onChange 瞎渲染，必须用 useCallback 锁住函数引用
  const onChartClick = useCallback((data) => {
    console.log("图表被点击", data);
  }, []);

  return (
    <>
      <input value={text} onChange={e => setText(e.target.value)} />
      {/* HeavyChart 必须用 React.memo 且 Props 必须是稳定的引用 */}
      <HeavyChart onClick={onChartClick} /> 
    </>
  );
}
```

**2. 极度消耗性能的昂贵计算**

如果你有一个循环了一万次的庞大计算逻辑，或者是复杂的正则匹配、大数组排序，这时候用 `useMemo` 缓存起来才是划算的。

JavaScript

```
// ✅ 正确示范：昂贵的计算
const sortedHeavyList = useMemo(() => {
  return heavyList.sort((a, b) => /* 极其复杂的排序逻辑 */);
}, [heavyList]);
```

**3. 作为其他 Hook 的稳定依赖项**

这也是极其常见的场景。当你的某个对象或函数，必须作为 `useEffect` 的依赖项时，如果你不用 `useMemo/useCallback` 把它锁住，会导致 `useEffect` 陷入无限死循环的重新执行。

### 👑 满分面试话术

面对这道题，你可以用下面这段话给出完美的架构师级回答：

“`useMemo` 和 `useCallback` 的本质是**空间换时间**，但很多时候我们忽略了它们自身的执行成本：包括闭包内存的分配、以及依赖数组在每次渲染时的浅比较开销。

因此，我们要遵循‘非必要不缓存’的原则。对于简单的逻辑运算，或者直接传递给原生 DOM 元素的事件函数，绝对不要使用它们，这往往会导致负优化。

它们真正的应用场景只有三个核心地带：

第一，当进行非常耗时的复杂计算时，用 `useMemo` 避免重复执行。

第二，当组件的 Props 需要传递给被 `React.memo` 包裹的、极其沉重的子组件时，必须用 `useCallback` 或 `useMemo` 保证引用的稳定性，否则 `React.memo` 的浅比较会失效，子组件依然会被迫重新渲染。

第三，当引用类型数据（对象/函数）被作为 `useEffect` 等其他 Hook 的依赖项时，需要用它们来保持引用的稳定，防止触发意料之外的无限死循环或重复请求。”
