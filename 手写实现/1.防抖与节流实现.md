# 如何手写防抖和节流？

## 问题

请使用 JavaScript 实现防抖和节流。防抖要求连续触发时只执行最后一次；节流要求一段时间内最多执行一次。两者都要正确传递参数和动态 `this`。

## 30 秒口述答案

防抖是在每次调用时清除旧 timer 并重新计时，所以连续触发只保留最后一次，适合搜索框和自动保存。节流是记录上一次执行时间，只有间隔达到限制才再次执行，适合滚动和拖拽事件。两者都通过闭包保存状态，并用普通函数取得调用时的 `this`。

## 详细原理

### 防抖

每次调用都清除上一个 timer，再创建新的 timer。只有等待期间没有再次调用，回调才会执行。因此多次连续输入会合并为最后一次操作。

### 节流

记录上一次真正执行的时间。新调用与上次执行时间的间隔小于 `wait` 时直接忽略，达到间隔后立即执行。本题使用的是时间戳版首部节流，不会补一次尾部调用。

### 使用边界

`setTimeout` 的时间表示最短等待目标，不保证精确时刻。防抖和节流只能减少函数启动次数，不能取消已经发出的网络请求，也不能解决旧响应覆盖新状态的问题。

## JavaScript 示例

运行环境：现代浏览器或 Node.js 23.11.1。

```javascript
function debounce(fn, wait) {
  let timer = null; // 闭包里的定时器

  return function (...args) {
    // 每次触发，都把前一个定时器砸掉
    if (timer) clearTimeout(timer);
    
    // 重新设一个定时器
    // 重点：这里用箭头函数，直接继承外层 return function 的 this，无需再写 const context = this
    timer = setTimeout(() => { 
      fn.apply(this, args); 
    }, wait);
  };
}

function throttle(fn, wait) {
  let lastTime = 0; // 记录上次执行的时间

  return function (...args) {
    const now = Date.now();
    // 如果现在的时间减去上次执行的时间，超过了等待时间，就执行
    if (now - lastTime >= wait) {
      fn.apply(this, args);
      lastTime = now; // 更新最后执行时间
    }
  };
}

const save = debounce((value) => console.log("保存", value), 300);
save("v1");
save("v2"); // 最终只执行这次

const onScroll = throttle(() => console.log("处理滚动"), 200);
onScroll();
onScroll(); // 时间窗口内被忽略
```

每次调用的时间复杂度和额外空间都是 `O(1)`。

防抖

这是一个基础版的防抖，满足了绝大多数搜索框联想的场景。但在实际生产环境（比如 lodash）中，我们通常还会给返回的函数挂载一个 `cancel` 方法。因为如果组件销毁了，但定时器还没走完，可能会引发内存泄漏或者操作已卸载组件的错误。

节流
我写的这个是**时间戳版本**，它的特点是‘首发立即触发’，但最后一次操作如果在冷却期内，就会被抛弃（没有尾部触发）。如果在实际业务中，我们不仅需要限制频率，还必须保证用户的**最后一次操作一定要生效**（比如拖拽停止后的位置保存），我们还需要用 `setTimeout` 配合，做一个支持尾部调用的双重节流版本。” *(面试官内心：连节流的“首发/尾发”边缘场景都懂，而且知道业务痛点在哪，不用再问了，直接过！)*

## 常见追问

1. **搜索框和滚动监听分别适合哪一个？** 搜索框通常用防抖，滚动反馈通常用节流。
2. **怎样给防抖增加立即执行或取消能力？** 增加 `leading` 状态或在返回函数上挂载 `cancel`，清除闭包中的 timer。
3. **怎样实现尾部节流？** 窗口期内保存最后一次参数，并安排一个剩余时间 timer；这会比本题时间戳版更复杂。

## 易错点

- 返回箭头函数，导致动态 `this` 不能从调用位置取得。
- 防抖时忘记 `clearTimeout`，结果每次调用都会执行。
- 节流时每次调用都更新时间，导致高频事件可能一直不执行。
- 把防抖理解为请求取消或响应顺序保护。
