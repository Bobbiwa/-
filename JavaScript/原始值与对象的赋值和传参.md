# JavaScript 中原始值与对象在赋值和传参时有什么区别？

## 问题

JavaScript 中，把一个原始值或对象赋给另一个变量时分别发生了什么？把它们传给函数后，为什么修改对象属性会影响外部对象，而给形参重新赋值不会？JavaScript 到底是按值传递还是按引用传递？

<summary>查看答案</summary>
<h2>30 秒口述答案</h2>
<p>JavaScript 的赋值和函数传参传递的都是值，不存在能让形参直接改绑实参变量的“按引用传参”。原始值本身不可变，复制后两个变量各自保存这个值；对象也是一种值，赋值或传参后，新旧变量指向同一个对象，所以通过任一变量修改对象属性，另一边都能观察到。可是给形参重新赋一个对象，只会改变函数内部的局部绑定，不会改变调用方变量。<code>const</code> 只禁止重新赋值，不会让对象自动变成不可变对象。</p>
<h2>详细原理</h2>
<h3>1. 原始值与对象</h3>
<p>ECMAScript 的原始类型包括 <code>Undefined</code>、<code>Null</code>、<code>Boolean</code>、<code>String</code>、<code>Symbol</code>、<code>Number</code> 和 <code>BigInt</code>，其余可直接操作的复合值属于对象；函数本身也是对象。</p>
<p>原始值不可变。例如字符串方法不会在原字符串内部改字符，而是返回新值。变量可以从一个原始值重新绑定到另一个原始值，但这不是修改原始值本身。</p>
<p>对象具有 identity 和可变属性。两个变量保存同一个对象值时，它们观察的是同一个对象；修改其属性不是给这两个变量重新赋值。</p>
<h3>2. 赋值复制的是什么</h3>
<ul><li>对原始值赋值，右侧计算出的原始值被保存到左侧绑定中，之后重新赋值互不影响。</li><li>对对象赋值，右侧计算出的对象值被保存到左侧绑定中，并不会隐式克隆对象。因此两个绑定可以指向同一个对象。</li><li>工程交流中常把后一种情况简称为“复制了引用”，但不能由此推导出 JavaScript 函数是按引用传参。规范层面传入的是求值后的参数值。</li></ul>
<p>展开语法 <code>{ ...source }</code>、<code>Object.assign</code> 等只能复制一层自有属性；如果属性值仍是对象，新旧对象的该属性仍可指向同一个嵌套对象。它们不是通用深拷贝。</p>
<h3>3. 函数参数为什么表现不同</h3>
<p>调用函数时，每个实参表达式先求值，得到的值用于初始化对应的形参绑定。因此：</p>
<ul><li>形参接收原始值后，给形参重新赋值不会影响调用方绑定。</li><li>形参接收对象值后，通过形参修改该对象的属性，调用方能看到同一对象发生了变化。</li><li>给形参重新赋一个新对象，只会让局部形参改为保存新对象，不会改绑调用方变量。</li></ul>
<p>判断是否“按引用传参”的关键反例是：如果函数真的拿到了调用方变量本身的引用，那么给形参重新赋值也应该改掉调用方变量；JavaScript 并不会这样做。</p>
<h3>4. <code>const</code> 约束的是绑定</h3>
<p><code>const user = { name: &quot;A&quot; }</code> 禁止执行 <code>user = anotherUser</code>，但允许 <code>user.name = &quot;B&quot;</code>。若需要限制对象属性被修改，可以根据场景使用 <code>Object.freeze</code>、不可变更新或只读类型；其中 <code>Object.freeze</code> 默认也只是浅冻结。</p>
<h2>JavaScript 示例（Node.js 23）</h2>
<pre><code class="language-javascript">&quot;use strict&quot;;&#10;&#10;let count = 1;&#10;let copiedCount = count;&#10;copiedCount = 2;&#10;console.log(count, copiedCount); // 1 2&#10;&#10;const original = { profile: { name: &quot;小杜&quot; } };&#10;const alias = original;&#10;alias.profile.name = &quot;Du&quot;;&#10;console.log(original.profile.name); // Du&#10;console.log(alias === original); // true&#10;&#10;function update(user, number) {&#10;  user.profile.name = &quot;updated&quot;; // 修改双方共享的对象&#10;  user = { profile: { name: &quot;local&quot; } }; // 只改绑局部形参&#10;  number = 99; // 只改绑局部形参&#10;  return { user, number };&#10;}&#10;&#10;let outsideNumber = 10;&#10;const returned = update(original, outsideNumber);&#10;&#10;console.log(original.profile.name); // updated&#10;console.log(outsideNumber); // 10&#10;console.log(returned.user.profile.name); // local&#10;console.log(returned.user === original); // false&#10;&#10;const shallowCopy = { ...original };&#10;shallowCopy.profile.name = &quot;shared nested object&quot;;&#10;console.log(original.profile.name); // shared nested object&#10;console.log(shallowCopy === original); // false&#10;console.log(shallowCopy.profile === original.profile); // true</code></pre>
<p>对象赋值和传参在语言语义上不会遍历或克隆对象内容；常见实现只复制内部的引用式值，但 ECMAScript 不规定具体存储方式或时间复杂度。对象展开需要枚举一层属性，成本会受被复制属性数量及访问行为影响，且不会递归复制嵌套对象。</p>
<h2>常见追问</h2>
<ol><li><strong>为什么很多资料会说对象是“引用传递”？</strong> 这通常是在描述多个变量能够访问同一对象的现象。更严谨的说法是对象值按值传递；形参拿到同一个对象值，但拿不到调用方变量的绑定。</li><li><strong><code>const</code> 对象为什么还能修改？</strong> <code>const</code> 限制变量绑定不能重新赋值，不限制对象内部属性；它与对象是否可变是两个维度。</li><li><strong>展开语法能解决对象互相影响吗？</strong> 只能切断最外层对象的 identity；嵌套对象仍然共享。是否需要 <code>structuredClone</code> 或业务化深拷贝，要看值类型、性能和语义要求。</li></ol>
<h2>易错点</h2>
<ul><li>把“共享同一对象”直接说成“JavaScript 按引用传参”，忽略形参重新赋值不会影响实参绑定。</li><li>认为原始值存在可被原地修改的内部内容；实际上改变变量只是让绑定保存另一个值。</li><li>认为 <code>{ ...object }</code> 是深拷贝，忽略嵌套对象仍然共享。</li><li>认为 <code>const</code> 会递归冻结对象，或认为 <code>Object.freeze</code> 默认会递归冻结嵌套对象。</li><li>把 <code>null</code> 当成对象；<code>typeof null === &quot;object&quot;</code> 是历史兼容结果，<code>null</code> 在语言类型中仍是原始值。</li></ul>
